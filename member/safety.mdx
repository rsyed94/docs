Open in Passport: [Rules](https://passportmcp.com/#rules)

**Rules** decides every action your agents take through Passport, instantly. It asks you only when a rule says so, and every decision names its cause, such as "Asked: Production changes ask first." Most rules come from your answers to asks, so the page is mostly a readout you correct.

## How a decision is made

Every action is decided the same way, whether it's a tool call, a command through the CLI guard, or `passport exec`. The first step that applies decides:

1. **Access**: what you may do with the app, set under **Who can use it** on its page, and whether an admin kept the tool off. No access blocks everything; **Read-only** runs only reads. Nothing below gets past it.
2. **Specific rules**: a block always wins, then the most specific rule.
3. **Team minimum**: your team's least careful choice for that environment. A rule can't be looser than it.
4. **Your choice** for the environment.

An irreversible action always asks unless a specific rule names that exact action. An app's **Tools** section shows the answer for each tool before any agent calls it: **Allowed**, **Asks**, or **Withheld**. See [Apps](/member/apps#tools).

## Actions and environments

Each action is one of four classes:

- **Read**: looks at something.
- **Change**: creates or edits.
- **Delete**: removes or overwrites. Rollbacks, secret changes, and schema migrations count.
- **Irreversible**: can't be taken back even with a backup, such as sending money or email, force-pushing the default branch, or deleting a repository.

Each action also runs in an environment: **Production**, **Staging**, or **Development**. Passport reads it from the action, such as a Railway environment, a Vercel target, a Supabase project or branch, a Neon branch, or a flag like `--environment`. When an agent names a resource only by its id, Passport asks that app once, with your own connection and only its read tools, and places the resource when the app's own facts are clear. Repository work lands where it goes: reads have no environment, a branch is Development, and code that reaches a repository's default branch counts as Production until you place that repository. Local work, such as installs, builds, and tests, has no environment. See [Where an action lands](/member/work#where-an-action-lands).

Apps without environments, like Linear, Notion, and Slack, are **Other apps**.

### How Passport knows

Passport places a command the way the vendor's own CLI picks where it goes. The first answer wins:

1. **A flag** on the command, such as `-e staging` or `--prod`.
2. **The folder's link**, such as `railway link`, `.vercel/project.json`, `supabase link`, or a `DATABASE_URL` in `.env`.
3. **The vendor's default**, such as `vercel deploy` going to Preview.
4. **Your workspace's choice** for that resource.
5. **Its name**: whole words like `prod`, `staging`, `qa`, `dev`, or `preview`. `domain` doesn't count as `main`.
6. **Nothing**: it counts as Production, and the decision says so.

Railway, Supabase, and Neon links hold an id. Once a resource is placed, the id decides, so a renamed environment keeps its place. A name in a link file never makes anything looser: for an id nobody placed, Passport asks your connected app for its real name. If a link file can't be read, the command counts as Production. A database URL is read only for its host: a local database is Development. Passport never sends or stores the URL, user, or password.

Each decision says how Passport knows: "Runs: Staging changes run on their own (linked in this folder)." Each app's page lists its resources under **Environments**, where an admin places them. When an ask waits on a resource nobody placed, it offers **It's Staging, always run** and **It's Development, always run**: choosing saves it for the workspace and runs the action once. Anyone can say Production; anything looser needs an admin. A change applies to new actions only. Run `passport env` in a folder to see what Passport reads there.

## By environment

The table at the top of **Rules** has one row per environment and one choice per row:

| Choice | Reads | Changes | Deletes | Irreversible |
| --- | --- | --- | --- | --- |
| **Ask before changes** | Run | Ask | Ask | Ask |
| **Ask before deletes** | Run | Run | Ask | Ask |
| **Ask only for irreversible** | Run | Run | Run | Ask |

The rows are **Production**, **Staging**, **Development**, **Not placed**, and **Other apps** when you use them. **Not placed** can't be set: anything Passport can't place counts as Production. The defaults are **Production: Ask before changes**, **Staging: Ask before deletes**, **Development: Ask only for irreversible**, and **Other apps: Ask before deletes**. Each change saves as you make it.

Your team may require a minimum for an environment, such as "Your team requires at least “Ask before changes”." Looser choices are off the table there; you can always pick something stricter.

With **Ask only for irreversible**, a delete runs only when Passport can take a backup first; otherwise it asks: "Couldn't take a backup first, so Passport is asking." From the shell, the guard backs up everyday deletes on your computer first, such as `rm` in the project (Claude Code), `git reset --hard`, `git clean`, dropped stashes, and branch deletes, so those run. Deleting folders a build makes again, such as `node_modules`, `dist`, or `.next`, runs with nothing to back up. See [Backups and undo](/member/undo).

Below the table, one line says who approves Production asks, such as "Production deletes need someone else to approve: Maya." It shows once your workspace has a second person. See [Production approvers](/admin/slack-and-approvers#production-approvers).

## Safeguards

- **When Passport can't be reached**: what the CLI guard does when it can't reach Passport. **Ask** (the default), **Block**, or **Run**. An unattended agent or Codex can't ask, so Ask blocks there. Run never applies to irreversible actions or to anything your team requires. See [When Passport can't be reached](/member/cli-hook#when-passport-cant-be-reached).
- **Run deletes Passport can't back up**: shown for rows on **Ask only for irreversible** other than Production. On, those deletes run without a backup; off, they ask first.
- **Stop retry loops**: on by default. When the same command fails 5 times in a row in one task, the guard asks before it runs again; with nobody there to ask (and on Codex), it blocks it. From the 3rd failure the agent is told to stop retrying and read the error.

## Specific rules

A specific rule runs, asks about, or never runs one action, an app, or a class of actions, in one environment or all of them. Most come from answering an ask with **Always allow…**. Each row says what it does, such as "Run railway redeploy", its environment, where it came from ("You, from an answer · Oct 25"), who it covers when that isn't just you, and **Until** a date when it expires. **New** marks rules learned this week, listed first. **Remove** asks first.

The most specific rule wins, the strictest wins among equals, and a block always wins. Your list also shows rules your team or the whole workspace set for you.

### Rules from your repositories

When an agent session starts in a repository, the [CLI guard](/member/cli-hook) reads its AGENTS.md and CLAUDE.md on your computer and looks for lines that say never to run a command Passport recognizes, such as "Never run `railway up`." Admins see each line, exactly as written and with the file it came from, at the top of **Specific rules**. **Enforce** adds a block for that command in that repository only; **Dismiss** keeps it from coming back. When an agent tries it there, the guard says "Blocked by this repo's AGENTS.md: Never run `railway up`." Only the line is sent, never the rest of the file.

At the start of each Claude Code session, the guard also tells the agent, in a few lines, what is true for the folder: where Production is, which keys Passport holds, what the repository's rules block, and what your Production rules ask.

## Everyone

Owners switch **Rules** to **Everyone** for what binds the whole workspace:

- **By environment** sets each team's minimum, or everyone's. Pick the team in **Whose**. **Anyone chooses** sets no minimum.
- **Production approvers**, with **Change**. See [Production approvers](/admin/slack-and-approvers#production-approvers).
- **Safeguards**: **Require the guard**, for everyone or one team. See [Guard required](/member/cli-hook#guard-required). **One deploy at a time** (on unless you turn it off) makes agents take turns deploying to, or migrating, the same Staging or Production target. See [One deploy at a time](/member/cli-hook#one-deploy-at-a-time).
- **Specific rules** for teams, the workspace, and other people.
- **Data checks**, on Enterprise. See [Data checks](/admin/data-checks).

## When Passport asks

When an action needs you, Passport shows one ask, the same in Passport, Slack, a notification, and your agent: who wants to do what ("Claude Code wants to deploy acme-worker"), where it lands, why Passport asked, what happens if it goes wrong (such as "Deploys can be rolled back in Railway." or "This can't be undone."), and the command. Your choices, each only when it applies:

- **Run once**: this action, this time.
- **For this task**, named by what it allows, such as **Railway changes in Staging for this task**: every action of that kind, on that app, in that environment, runs without asking until the task ends (its agent says it's done, it's quiet for 30 minutes, you stop it, or 12 hours pass). Never offered for an irreversible action or a Production delete. The task's page lists what it allows, and **Revoke** takes effect on the agent's next command.
- **It's Staging, always run** or **It's Development, always run**: places a resource nobody placed, for the whole workspace, and runs this action.
- **Always allow…**: saves a specific rule.
- **Don't run**, with an optional note the agent receives.
- **Stop {agent}**: for an agent token or cloud agent, stops it until someone resumes it; for an agent on a computer, ends its task. The ask is declined too.

In Passport, the buttons are **Don't run**, **For this task** (when it's offered, with one line above them saying what it allows), and **Run once**; the rest are under **More choices**. Many agents show the question right where you're working; it also waits in **Waiting on you** on [Work](https://passportmcp.com/#work). With notifications on, you can choose **Run once**, **For this task**, or **Don't run** from the notification, and opening it shows every choice.

An agent can also ask up front for what its plan needs: "Claude Code wants, for this task: Railway changes in Staging, Supabase changes in Development", with its reason. **Approve all** allows each one for the task; **Decline** allows none. Agents ask with `passport request --task "railway changes in staging"` or, over MCP, `passport_request_access` with `duration: "task"`.

### Confirm it's you

Approving a Production change or delete, or anything irreversible, takes a fresh check that it's you: Passport opens **Confirm it's you**, and you use your passkey or choose **Email me a code instead**. You add passkeys under **Security** in [Settings › Account](https://passportmcp.com/#settings/account). These asks are approved in Passport only: Slack offers **Review in Passport**. Your own agent's prompt can still approve a Production change you asked for at your keyboard, but never an irreversible action. Declining never needs a check.

Saving a rule change that lets agents make Production changes with less checking takes the same check, such as a looser Production choice, a lower team minimum, removing a block, or placing a resource out of Production. Changes that tighten, or touch only Staging, Development, or reads, save as they are. The CLI and API can't show the check, so they're refused with a link to change it in Passport.

### How long an ask waits

An ask for a command your agent wants to run stays open for a day. An ask for an app's tool in your agent's own prompt stays open for about three minutes. If your rules change while an ask waits and would now run the action, it resolves itself.

When your team routes an ask to someone else, your own ask says who it's waiting on, like "Waiting on Maya". If nobody answers in time, it also goes to your admins.

### When the agent stopped waiting

The guard holds a command for a few seconds, and an agent's turn can end while a command waits for you. You can still approve it for a day: "The agent stopped waiting. Approving lets it run the next time the agent tries it."

The approval is a one-time pass for that exact command in that task. It runs once, the next time the agent tries the same command there, and lapses a day after you approve. A different command, or another task, asks again. Passport never runs the command itself. A decline stays final.

## Agents you own

Your rules also govern the agents whose tokens you own. An agent can't answer a prompt, so its ask waits in your **Waiting on you**, naming the agent. A token with no owner is blocked from anything that would need a person. See [Agent tokens](/member/agents#agent-tokens).
