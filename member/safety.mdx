Autopilot decides every action your agents take through Passport, instantly, from your rules. It asks you only when a rule says so, and every decision names its cause, such as "Asked: Production changes ask first (Careful)."

## Actions and environments

Each action is one of four classes:

- **Read** — looks at something.
- **Change** — creates or edits.
- **Delete** — removes or overwrites. Rollbacks, secret changes, and schema migrations count.
- **Irreversible** — can't be taken back even with a backup: sending money or email, force-pushing the default branch, deleting a repository.

Each action also runs in an environment: **Production**, **Staging**, or **Development**. Passport reads it from the action, such as a Railway environment, a Vercel target, a Supabase project or branch, a Neon branch, or a CLI flag like `--environment`. When an agent names a resource only by its id, Passport looks up its name once with your own connection to that app, using one of the app's read tools, and places it by name. If an app has environments but Passport can't place the resource, it counts as Production, and the decision says so.

Apps without environments, like Linear, Notion, and Slack, are **Other apps**.

### How Passport knows

Passport places a command the way the vendor's own CLI picks where it goes. The first answer wins:

1. **A flag** on the command, such as `-e staging` or `--prod`.
2. **The folder's link**, such as `railway link`, `.vercel/project.json`, `supabase link`, or a `DATABASE_URL` in `.env`.
3. **The vendor's default**, such as `vercel deploy` going to Preview.
4. **Your workspace's choice** for that resource.
5. **Its name**: whole words like `prod`, `staging`, `qa`, `dev`, or `preview`. `domain` doesn't count as `main`.
6. **Nothing**: it counts as Production, and the decision says so.

A name in a link file never makes anything looser. Railway, Supabase, and Neon links hold an id, so Passport asks your connected app for the real name, and an id nobody has placed counts as Production until someone chooses. The id decides: if the name in a link file differs from the one Passport saved, the environment was renamed, so it keeps its place and shows the new name. If a link file can't be read, the command counts as Production. A database URL is read only for its host: a local database is Development; Passport never sends or stores the URL, user, or password.

Each decision says how Passport knows: "Runs: Staging is Hands-off (linked in this folder)." In **Rules → Environments**, each resource shows where it came from: **Linked in a folder**, **From a name**, or **Set by** whoever chose. When an approval is waiting on a resource nobody has placed, the request shows **This is: Production · Staging · Development**. Choosing saves it for the whole workspace and decides the action again, so it may run right away. Anyone can say Production; anything looser needs an admin. Changing an environment in Rules or with `passport env set` applies to new actions only: a request that's already waiting keeps the environment it was raised with.

Run `passport env` in a folder to see what Passport reads there.

## Presets

For each environment, and for Other apps, choose how much agents can do on their own:

| | Careful | Balanced | Hands-off |
| --- | --- | --- | --- |
| Reads | Run | Run | Run |
| Changes | Ask | Run | Run |
| Deletes | Ask | Ask | Run |
| Irreversible | Ask | Ask | Ask |

The defaults are **Production: Careful**, **Staging: Balanced**, **Development: Hands-off**, and **Other apps: Balanced**. Irreversible actions always ask unless an exception allows that one action. Your team may require a minimum preset for an environment; you can always pick something stricter.

## Exceptions

An exception runs, asks about, or blocks a specific action, an app, or a class of actions, in one environment or all of them. The most specific exception wins, the strictest wins among equals, and a block always wins. Admins can add exceptions for a team or everyone.

## When Passport asks

When an action needs you, you can **Approve once**, **Approve for this session**, **Always allow** (which saves an exception), or **Decline** with a note the agent receives. Many agents show the question right where you are working; it is also waiting in **Approvals**, and in a notification with Approve and Decline buttons if you turned notifications on.

An approval asked in your agent's own prompt stays open for about three minutes. One asked while nobody was at the keyboard, such as a background or CI run, waits for a day. If your rules change while a request is waiting and would now run the action, the request resolves itself.

## Agents you own

Your rules also govern the agents whose keys you own. An agent can't answer a prompt, so its request waits in your **Approvals**, naming the agent that asked. An agent key with no owner is blocked from anything that would need a person: assign it an owner in **Agents**.
