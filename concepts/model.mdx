A few ideas make the rest of Passport easier. You can skim this once, then jump back to the quickstarts.

## Workspace

A workspace is your team's space in Passport. It holds people, connected apps, teams, settings, Activity, and billing. One workspace cannot see another. You can belong to more than one and switch between them.

## People and roles

Everyone in a workspace is a member (or an automation identity). There are three roles:

<CardGroup cols={3}>
  <Card title="Admin" icon="user-shield">
    Approves apps, manages people and teams, sets rules, and can see the audit trail. The first person in a workspace is an admin.
  </Card>
  <Card title="Member" icon="user">
    Connects AI assistants and uses the apps their access allows.
  </Card>
  <Card title="Agent" icon="robot">
    An automation identity for scripts and CI. Signs in with an agent key instead of a browser session.
  </Card>
</CardGroup>

Deactivating someone signs them out everywhere and revokes their connected accounts right away.

## Apps (and MCP)

In the product, **Apps** is where you browse and connect tools your AI assistants can use — GitHub, Linear, Stripe, and so on.

Under the hood, Passport may reach the provider through **MCP** (Model Context Protocol) or through a reviewed API driver. You usually do not need that distinction day to day: both use the same Connect, access, safety, and Activity experience, and both reach AI assistants through Passport's MCP endpoint. These docs use "app" unless the technical detail matters.

Apps can connect in different ways: through a managed API driver, by MCP URL, as a hosted MCP command, as a demo for evaluation, or as install-on-your-machine instructions that do not go through Passport's gateway. See [Managed API integrations](/admin/managed-api-integrations).

Each app has a short key (for example `github`) and an auth mode:

- **Company account** — one shared login for everyone
- **Your account** — each person connects their own (Passport opens the provider sign-in when needed)
- **None** — no upstream login

Admins can turn individual tools on or off inside an app.

## Access (passes)

A **pass** is what a person may do with an app:

<CardGroup cols={3}>
  <Card title="Full" icon="unlock">
    Every tool, including writes.
  </Card>
  <Card title="Read-only" icon="glasses">
    Only tools that are clearly read-only. Write tools are hidden, not just refused.
  </Card>
  <Card title="None" icon="ban">
    No access. The app is not shown to that person.
  </Card>
</CardGroup>

Access is layered: workspace default (or selected people only), then team rules, then per-person overrides. The most specific rule wins.

## Teams

A team groups people (stored as each person's department). Grant access by team — for example "Support gets read-only GitHub" — instead of person by person. With SCIM, IdP groups map to Passport teams.

## Bundles

A **bundle** (Enterprise) is a curated set of tools from several apps, with its own connection URL. Use it when an AI assistant should see a tight tool set instead of everything a person can reach. See [Bundles](/admin/bundles).

## AI clients

An **AI client** is the assistant that calls Passport — Claude, Cursor, ChatGPT, VS Code, Codex, Passport CLI, and others. Local apps can connect through the setup Passport shows or the optional macOS desktop app. Hosted apps use a connection URL and browser sign-in. Terminal and CI can use [Passport CLI](/quickstart/cli).

Admins can require recognized clients only, and allow or block unlisted ones. See [Client fleet](/admin/client-fleet).

## How a call flows

When an AI assistant uses a tool through Passport, Passport:

1. Checks who is calling and what they are allowed to use
2. Scans the request with guardrails
3. Calls the app on their behalf
4. Scans the result
5. Records the call in Activity
6. Returns the result

There are a few connection shapes (workspace, single app, or bundle). Disabling an app removes its tools from every client right away. A person's own pause switch does the same for just them.

<Accordion title="Technical connection URLs">
  | URL | Purpose |
  | --- | --- |
  | `/mcp` or `/w/{workspace}/mcp` | Whole workspace (hosted connectors use the `/w/…` form) |
  | `/s/{appKey}/mcp` | One app |
  | `/b/{bundleKey}/mcp` | One bundle |

  For CLI agent keys, set `PASSPORT_ENDPOINT` to the workspace URL (`/w/ws_…/mcp`). See [Passport CLI](/quickstart/cli).
</Accordion>
