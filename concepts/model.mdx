Passport sits between an agent and the work app it wants to use. It keeps the app credential, checks access and Safety, makes the call, and records the outcome.

## The five things to know

### Workspace

A workspace is your team's private space in Passport. It holds people, apps, settings, and Activity. Workspaces are isolated from one another, and you can switch if you belong to more than one.

### Apps

An app is something your agent can use through Passport, such as GitHub, Linear, Stripe, or Notion. Open **Apps** to browse, connect, and manage them.

Some apps connect through MCP. Others use a reviewed API integration. Passport gives both the same connection, access, Safety, and Activity experience, so most people do not need to care which technology is underneath.

### Agents

An agent is where you use AI: Claude, Cursor, ChatGPT, VS Code, Codex, Passport CLI, or another MCP-compatible product. Open **Agents** to add one, see its connection status, disconnect it, or choose which available apps it can see.

### Access

Access answers one question: what may this person do with this app?

<CardGroup cols={3}>
  <Card title="Full" icon="unlock">
    Read and write tools are available.
  </Card>
  <Card title="Read-only" icon="glasses">
    Write tools are hidden from the agent.
  </Card>
  <Card title="None" icon="ban">
    The app is not shown to that person.
  </Card>

Enterprise admins can set access for the workspace, a team, or a person. A more specific choice wins. A person's agent-level app selection can narrow access further, but can never grant more.

### Activity

Every call through Passport creates an Activity record with the person, agent, app, action, outcome, and timing. Members see their own records. Enterprise admins can review the workspace-wide log in **Audit**.

## What happens during a call

<Steps>
  <Step title="Identify the person and agent">
    Passport checks the signed-in identity and the connection being used.
  </Step>
  <Step title="Apply access and Safety">
    Apps or actions that are not allowed are hidden, blocked, or held for approval.
  </Step>
  <Step title="Inspect the request">Guardrails check outgoing arguments before Passport contacts the app.</Step>
  <Step title="Call the app">Passport uses the connected account on the person's behalf.</Step>
  <Step title="Inspect and record the result">
    Guardrails check the result, then Passport writes Activity and returns the safe response.
  </Step>
</Steps>

## People, teams, and automation

- **Admins** manage the workspace and its rules.
- **Members** connect agents and use the apps available to them.
- **Agents** are the AI tools connected to Passport, such as Claude Code, Codex, or Cursor.
- **Automation credentials** connect scripts and CI through Passport CLI.
- **Teams** let Enterprise admins apply access and agent defaults to a group instead of one person at a time.

Deactivating a person revokes their sessions, agents, and connected accounts immediately.

## Advanced building blocks

- A [bundle](/admin/bundles) combines a curated set of tools from several apps behind one connection.
- [Tool discovery modes](/concepts/discovery) control how a large tool catalog is presented to an agent.
- [Managed API integrations](/admin/managed-api-integrations) connect reviewed provider APIs through the same Passport gateway.

<Accordion title="Technical connection URLs">
  | URL | Purpose |
  | --- | --- |
  | `/mcp` or `/w/{workspace}/mcp` | Whole workspace (hosted connectors use the `/w/…` form) |
  | `/s/{appKey}/mcp` | One app |
  | `/b/{bundleKey}/mcp` | One bundle |

Most people should copy the connector address shown under **Agents → Add agent**. For CLI agent keys, set `PASSPORT_ENDPOINT` to the workspace URL (`/w/ws_…/mcp`). See [Passport CLI](/quickstart/cli).

</Accordion>
