## Tools do not show up after connecting

What to do depends on how you connected:

- **Local apps set up through Passport Desktop or the local bridge** (Claude Desktop, Cursor, VS Code, and similar): new apps usually appear within about 15 seconds. If nothing shows, restart the AI app once. Passport says this when you connect: "will pick this up in ~15 seconds (restart if it doesn't appear)."
- **ChatGPT or Claude.ai:** refresh or reconnect the connector in that product after an approval or account change.
- **Passport CLI:** run `passport status`, then `passport search` again. If an app is missing, check that it is enabled for that client under **AI Clients** in Passport.
- **Claude Code or Codex** connected the native way: start a new session so tools refresh.

## Restart the AI app once after connecting

Some local AI apps remember their tool list from launch. After you connect an account or an admin enables an app, if tools have not appeared within about 15 seconds, restart that app once. ChatGPT, Claude.ai, and Passport CLI do not use this local refresh path.

## Claude shows every tool twice

You probably have both the Claude desktop connection and the Claude.ai connector turned on. The Claude.ai connector also syncs into Claude Desktop, so running both duplicates tools.

The desktop app warns on the Claude row: "Also covered by your Claude.ai connector. Remove one to avoid duplicate tools." Disconnect one of the two.

## "Redirect URI is not allowed" when signing into an app

Some apps (Mintlify is one example) only allow sign-ins that return to domains you have allowlisted in **their** settings. The fix is in that provider's dashboard, not in Passport.

Add your Passport domain (or the full callback URL) to their allowed redirect settings:

```
https://<your-passport-domain>/auth/connect-app/callback
```

Admins can copy this from the app's Manage panel under "Sign-in service", or from the Add-an-app screen when the app signs in per person ("Callback URL").

On Mintlify: Admin → MCP → "Allowed OAuth redirect URIs" → Add domain. That is different from Mintlify's "custom domain" DNS screen for hosting docs. If your org has more than one Mintlify deployment, allow the redirect on each one, or pick the specific deployment on the consent screen.

## "A different workspace" / reconnect prompts

Passport will not attribute your activity to the wrong workspace. If this machine's saved Passport sign-in belongs to a different workspace than the one a client expects, you may see:

- In the desktop app: "Connected to another workspace (...). Reconnect to use ..."
- From the bridge: "This machine's Passport credential now belongs to a different workspace. Reconnect this client from the Passport app."

Reconnect that client from Passport. This often happens after signing the same computer into a second workspace.

## "This connection isn't signed in"

Your AI assistant's connection is no longer signed in. Open Passport and reconnect that AI client.

## "This account has been deactivated"

A deactivated person cannot sign in or use Passport. You may see:

- From a connection: "This account has been deactivated."
- On the sign-in page: "Your account has been deactivated. Contact your workspace admin."

An admin can reactivate you in People; then reconnect your own accounts.

## Rate limited

Passport limits how fast connections can call tools. When you hit a limit, wait a moment and try again. The message says whether it is this connection, the whole workspace, or too many requests at once. Self-host operators can tune the caps; see [Self-host](/self-host).

## Passport CLI exits with an error code

Stable exit codes help scripts and agents:

| Code | Meaning |
| --- | --- |
| `2` | Sign in again |
| `3` | Connect the named app |
| `4` | Approval is pending |
| `5` | Blocked by policy, a guardrail, client selection, or a denied approval |
| `6` | Invalid command or tool name |
| `1` | Other failure (including unclear network errors) — do not auto-retry |

Run with `--json` for a structured `cause` and any approval or app hint.
