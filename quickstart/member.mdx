Passport gives you one place to connect the apps available to you and use them from every supported AI client. Windows, Linux, and macOS all use the same default path: **Browse apps → Add client → use the client-native installer, `passport login`, or the connector URL**. The macOS app is an optional accelerator, not a requirement.

## Accept your invite

Open the invite email and click the link. It signs you into your workspace. Keep that link handy: any Passport link that contains your workspace works to sign in later, including your invite link and your workspace's Passport page URL.

## 1. Browse apps

Open **Apps**, choose an app, and select **Connect**. Passport connects it immediately when your workspace allows it, or explains the review or setup that remains.

For an MCP that uses your own account (such as GitHub), Passport opens your browser to authorize with that provider, then brings you back. You authorize as yourself, and the AI client never sees a token or password. Connected accounts are brokered server-side, not written into any client config.

## 2. Add an AI client

Open **AI Clients → Add client** and choose the surface you use:

- **Terminal and automation:** install [Passport CLI](/quickstart/cli) on Windows, Linux, or macOS, run `passport login`, and finish browser confirmation.
- **Editors and coding agents:** use the supported one-click link, official one-line command, or copyable configuration shown by Passport, then complete browser OAuth.
- **Hosted and GUI clients:** paste the connector URL shown by Passport and sign in in the browser.
- **Several local macOS clients:** use the optional desktop app to wire supported clients in one pass.

<Tabs>
  <Tab title="Windows">
    1. Open Passport in your browser and choose **Add client**.
    2. Use the client-native setup shown, or install Node.js 20+ and Passport CLI.
    3. Complete browser OAuth, then ask the client to list your available Passport tools.
  </Tab>
  <Tab title="Linux">
    1. Open Passport in your browser and choose **Add client**.
    2. Use the client-native command/configuration, or install Node.js 20+ and Passport CLI.
    3. Complete browser OAuth, then ask the client to list your available Passport tools.
  </Tab>
  <Tab title="macOS">
    1. Use the same web, native MCP, or CLI path as Windows and Linux.
    2. Optionally install Passport Desktop to configure several local clients in one pass.
    3. Complete browser confirmation and verify each client in the install hub.
  </Tab>
</Tabs>

### Hosted clients (ChatGPT and Claude.ai)

Hosted clients cannot reach a local process, so they connect straight to the gateway with a connector URL of the shape:

```
https://<your-passport-host>/w/<your-workspace-id>/mcp
```

Your workspace id is the `ws_…` segment in that path (and in your Passport browser URL). Passport shows and copies the full connector address from **AI Clients → Add client**. The desktop app can copy it too, but is not required.

<Tabs>
  <Tab title="ChatGPT">
    <Steps>
      <Step title="Open connector settings">
        Go to ChatGPT's Connectors settings and click Create. If you do not see Create, enable Developer mode under Connectors, then Advanced first.
      </Step>
      <Step title="Paste the address">
        Paste the connector URL as the server URL and continue.
      </Step>
      <Step title="Allow">
        A Passport page opens. Click Allow and you are done. You approve as yourself; ChatGPT never sees a token or password.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Claude.ai">
    <Steps>
      <Step title="Open connector settings">
        Go to Claude.ai's connector settings and click Add custom connector. Anthropic currently allows custom connectors on Free (one connector) as well as Pro, Max, Team, and Enterprise; confirm the limit in your Claude account if Add custom connector is missing.
      </Step>
      <Step title="Paste the address">
        Paste the connector URL as the server URL and continue.
      </Step>
      <Step title="Allow">
        A Passport page opens. Click Allow and you are done. You approve as yourself; Claude.ai never sees a token or password.
      </Step>
    </Steps>
  </Tab>
</Tabs>

### Terminal and headless agents

Install and sign in once, then let terminal agents search for and run namespaced tools without loading a full MCP tool catalog into every session:

```sh
npm i -g passport-bridge
passport login --cloud https://passportmcp.com --workspace <workspace-id>
passport search "issues"
passport run github_search_issues '{"query":"SSO"}'
```

Use a named per-agent profile when you want separate client selection and attribution. For CI, use a governed agent key without a local credential file. See the [Passport CLI guide](/quickstart/cli).

### Optional macOS accelerator

The desktop app connects Claude, Claude Code, Cursor, VS Code, and Codex to your workspace in one pass. It is a universal build (Apple silicon and Intel) and requires macOS 11 (Big Sur) or later.

<Steps>
  <Step title="Download and open">
    Download the app from your workspace's download page, drag Passport to Applications, then right-click and choose Open the first time.
  </Step>
  <Step title="Sign in">
    Paste any Passport link containing your workspace. Confirm the short code in your browser and approve.
  </Step>
  <Step title="Connect local clients">
    Choose each client you want Passport to configure. Passport keeps a backup and never overwrites a config it cannot parse.
  </Step>
</Steps>

<Warning>
  If you run both the Claude desktop bridge and the Claude.ai connector, Claude will show each tool twice, because the Claude.ai connector also syncs into Claude Desktop. Keep just one of the two. See [Troubleshooting](/troubleshooting).
</Warning>

## 3. Prove the governed path

Open **Home** (Getting started) or **AI Clients** and find the activation checklist step **Prove the governed path**. Choose **Run setup check**. This built-in diagnostic is read-only, checks your observed client against the current workspace policy, does not contact the provider, and writes a real successful row to Activity. Passport opens Activity only after that succeeds. If a precondition changed, the checklist keeps the step incomplete and shows a retryable error.
