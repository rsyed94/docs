Open in Passport: [Agents](https://passportmcp.com/#agents)

Coding agents can read the keys on your computer. Passport lets them use your production apps without those keys, and production writes wait for you.

## 1. See which keys your agents can reach

```sh
npx passport-bridge@latest scan
```

Runs locally, with no account. Key and environment values never leave your computer. Once you’re signed in, the scan also sends your agents’ MCP server names and commands, never key values. See [the scan](/member/scan) for what it checks.

## 2. Set up Passport

```sh
npx passport-bridge@latest init
```

Needs Node.js 20 or newer. Init looks at everything first and shows one plan. Nothing changes until you say yes:

```text
Passport setup

  Scan       3 keys your agents can reach: GitHub, Railway, and Supabase
  Sign in    Opening your browser. Confirm code HJKT-WQRM.
             ✓ Signed in to Maya's workspace

  Plan       Connect Railway and Supabase on one sign-in page
             Add Passport to Claude Code and Cursor
             Turn on the guard in Claude Code and Cursor, so Passport checks
             each shell command first
  Edits      ~/.claude.json, ~/.cursor/mcp.json, ~/.claude/settings.json, and
             ~/.cursor/hooks.json. Keeps a backup of each.
  Done       ✓ GitHub connected
  Kept       – Your Railway key stays on this computer.

Use the recommended setup? (n to choose step by step) [Y/n]

  Apps       Opening one sign-in page for both. Press Enter to stop waiting.
             ✓ Railway   ✓ Supabase
  Agents     ✓ Claude Code   ✓ Cursor
  Guard      ✓ On in Claude Code and Cursor

Done.
  ✓ Railway and Supabase connected to Passport
  ✓ Passport added to Claude Code and Cursor
  ✓ Guard on in Claude Code and Cursor

Next: in Claude Code, run /mcp to sign in, then ask it to list your Railway
services.
```

Press Enter for the recommended setup, or type `n` to go step by step: each step then asks on its own, and you can skip any of them.

- **Sign in** creates your workspace if you're new. Already signed in on this computer? Init uses that sign-in.
- **Apps** covers Railway, Supabase, and GitHub when it finds a key or the app's CLI. If your workspace reviews new apps first, init says so and your admin gets the request. With no apps found, step by step lets you pick some.
- **Keys** stay on your computer: Passport doesn't hold keys, so your CLIs keep their own sign-ins and Passport decides each command first. Init lists the keys it found, so you know where an agent could read one. See [Keys and passport exec](/member/cli-hook#keys-and-passport-exec).
- **Agents** adds Passport's one address, `https://passportmcp.com/mcp`, to Claude Code, Codex, Cursor, and VS Code. Each agent signs you in through your browser the first time, so no key or token goes in its settings. An agent still on your workspace's own older address (`/w/ws_…/mcp`) or on a local bridge moves to the one address. For Claude Desktop, init copies the address for you to paste in **Settings › Connectors › Add custom connector**.
- **Guard** applies your rules to the commands agents run in your terminal, like `railway volume delete`. It can't see inside scripts, aliases, or `make` targets. See [the CLI hook](/member/cli-hook).
- **Where** lists the environments Passport placed, by environment. Anything it can't place yet counts as Production until you place it in the **Environments** section of its app's page.

Run init again any time. The plan shows what's already set up and changes only what's missing, including after you press Ctrl-C. When nothing is missing, it says so and asks nothing.

Questions only take what you type after they appear, so pressing Enter while init is busy never answers one. `--dry-run` prints the plan and changes nothing. Signed out, it shows the part on your computer without signing in: the agents it found, the files it would edit, and the guard. In a script or another agent, add `--yes` to use the recommended setup without asking; init then prints the sign-in page and moves on instead of waiting, and `passport connect --wait 300` waits for it later. `--json` without `--yes` prints the plan as JSON; `--yes --json` applies it and prints one summary with each step's status. `--skip-apps`, `--skip-agents`, and `--skip-guard` leave a step out, and `--no-open` prints links instead of opening a browser.

## What changes on your computer

| Where | What |
| --- | --- |
| `~/.passport/` | Your sign-in, and a copy of the Passport CLI that the hooks run |
| `~/.claude.json` | A `passport` server, added with `claude mcp add` |
| `~/.codex/config.toml` | A `passport` server, added with `codex mcp add` |
| `~/.cursor/mcp.json` | A `passport` server |
| VS Code's user `mcp.json` | A `passport` server |
| `~/.claude/settings.json`, `~/.codex/hooks.json`, `~/.cursor/hooks.json` | Passport's hooks |

Init changes only Passport's own entries. The plan names every file it edits before it edits any, and it saves each original once as `<file>.passport-backup`. It never edits your shell profile; to run `passport` from any terminal, add the `PATH` line it prints.

## Undo it

```sh
passport hook uninstall --agent claude-code --apply    # also codex, cursor
claude mcp remove --scope user passport
codex mcp remove passport
passport logout
```

Ran init with `npx` only? Use `~/.passport/cli/bin/passport` in place of `passport`. Then remove the `passport` entry from `~/.cursor/mcp.json` and from VS Code (**MCP: List Servers**), and delete `~/.passport/cli`. Your original settings are in the `.passport-backup` files if you want them back.
