Open in Passport: [Agents › Add agent](https://passportmcp.com/#agents?add=1)

Setting up your own computer? `npx passport-bridge@latest init` does it in one pass: see the [developer quickstart](/quickstart/developer).

Passport CLI is for terminal coding agents and automation. It reaches the same Passport as Claude, Cursor, and ChatGPT, with the same access, rules, approvals, and record.

Prefer the normal **Add agent** setup for apps with a GUI (Cursor chat, VS Code chat, Claude Desktop, Claude.ai, ChatGPT). Claude Code and Codex CLI can use either path; using the CLI doesn't sign out any other agent.

## Install and sign in

Works on Windows, Linux, and macOS. Needs Node.js 22.23.2 or newer.

<Tabs>

    passport version
    passport login
    passport status
    passport search ""

  <Tab title="Linux">

<Steps>
  <Step title="Install once">
    The `passport-bridge` package ships both `passport` and `passport-bridge`.

    ```sh
    npm i -g passport-bridge
    passport version
    ```

  </Step>
  <Step title="Sign in">
    Run `passport login`. It opens your browser. Sign in with Google, GitHub, or a code sent to your email, check that the code on the page matches your terminal, then click **Connect**. New to Passport? Name your workspace on the same page and you're in.

    ```sh
    passport login
    passport status
    passport doctor
    ```

    The terminal prints what to expect:

    ```text
    Sign in to Passport
      Code: HJKT-WQRM
      Link: https://passportmcp.com/cli?code=HJKT-WQRM (opened in your browser)
    Check the code matches the one in your browser before you approve.
    Waiting for the browser… (Ctrl-C to stop)

    Signed in as Erin Park to Acme.
    Run: passport status
    ```

    Check the code. A sign-in link someone else sends you shows their code, not yours, so a code that doesn't match means close the page. Codes expire after 10 minutes and work once. Nothing connects until you click **Connect**, and **Deny** stops the terminal. If you're already signed in to Passport in that browser, you'll see your workspace straight away; **Use a different account** picks another. Login stores a rotating credential in `~/.passport/credentials.json` with owner-only permissions and makes that profile active. Add `--verbose` to see the profile name and file.

    Already signed in? `passport login` says as whom and asks `Switch? [y/N]`. Enter keeps you signed in; `--switch` skips the question and lets the browser pick again.

    Already know the workspace? `passport login --workspace ws_…` takes you to it in the browser. Self-hosted deployments also pass `--cloud <origin>`. On SSH or another host without a browser, add `--no-open` so Passport prints the link instead of launching a browser; open it on any device:

    ```sh
    passport login --no-open
    ```

    Without a terminal (an agent's shell, a script) or with `--json`, sign-in is two steps, like `stripe login --non-interactive`. The first prints the link and code and exits; after the code is approved in the browser, run the `next_step` it printed to finish:

    ```sh
    passport login --json
    # {"status":"pending","verification_url":"https://passportmcp.com/cli?code=HJKT-WQRM","code":"HJKT-WQRM","next_step":"passport login --complete lgn_… --json",…}
    passport login --complete lgn_… --json
    ```

    To switch later on a computer with more than one profile, inspect and select the local active profile explicitly:

    ```sh
    passport profiles
    passport use cli@ws_…
    ```

  </Step>
  <Step title="Search, inspect, and run">
    `search` returns namespaced tool names. Pass one directly to `describe` or `run`; no name translation is required.

    ```sh
    passport search "issues"
    passport describe github_search_issues
    passport run github_search_issues '{"query":"SSO"}'
    ```

  </Step>
</Steps>

## Commands

| Command                                 | Purpose                                                                                                                                                    |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `passport init [--dry-run]`             | Set up this computer: one plan first, then one question. `--dry-run` shows the plan and changes nothing.                                                   |
| `passport status`                       | Your setup on one screen: you, your workspace, and this computer; each agent's guard and its fix; Autopilot; apps; keys.                                   |
| `passport wait <approval-id>`           | Wait for a person to decide an approval. While it is still waiting, prints the link and, on a terminal, a live countdown.                                  |
| `passport tasks [--status <s>]`         | Your agents' recent tasks and what Passport decided, running ones first. See [Work](/member/work#from-the-terminal).                               |
| `passport exec -- <cli> [args…]`        | Run a vendor CLI with a key Passport holds. `--ask-again` asks again after a recent decline.                                                               |
| `passport doctor`                       | Check Node, how your sign-in is stored, the server, your sign-in, and that this CLI and the server match. Never shows a key.                               |
| `passport search [query]`               | Find tools you can run. With no words, lists every tool you can run, by app.                                                                               |
| `passport describe <tool>`              | Print a tool's class (Read, Change, Delete, or Irreversible), description, and full parameters schema. JSON also exposes `name` and `inputSchema` aliases. |
| `passport run <tool> [json-args]`       | Execute a governed tool call. Use `--args -` for stdin or repeat `--set` / `--set-json`.                                                                   |
| `passport connect [app...]`             | Get or open a personal-account connection flow. Add `--wait <sec>` to wait for completion.                                                                 |
| `passport resources [uri]`              | List resources or read one URI.                                                                                                                            |
| `passport prompts [name]`               | List prompts or get one, with repeatable `--set key=value` arguments.                                                                                      |
| `passport scan`                         | Find keys your agents can reach. Signed in, also report the MCP servers set up in your agents. Managed-policy violations exit `5`.                         |
| `passport completion <bash\|zsh\|fish>` | Generate shell completion locally without a profile or network request.                                                                                    |
| `passport profiles` / `use <name>`      | List local profiles or select the active profile without network access.                                                                                   |
| `passport login` / `logout`             | Create or revoke a named local profile.                                                                                                                    |
| `passport ready --json`                 | Report machine-readable local readiness for automation.                                                                                                    |
| `passport help [verb]` / `version`      | Inspect the CLI without a profile or network connection.                                                                                                   |

Every command accepts `--profile`, `--json`, `--timeout`, `--quiet`, and `--caller`.

On a terminal, output wraps to your window (at least 40 columns) and a line that updates in place, like a countdown, always fits on one row. Piped output never wraps and has no color, so scripts read the same lines at any width. `NO_COLOR` turns color off, and `--json` output only ever gains fields.

### Waiting for a person

When your rules ask first, `passport exec` and `passport wait` print the approval link right away, then keep one line up to date on a terminal:

```text
Passport: railway redeploy changes Production.
Approve it on your phone or open:
https://passportmcp.com/#approvals?approval=apr_…&workspace=ws_…
Waiting for Erin · 1:32 left
```

Press Ctrl-C to stop waiting: the request stays open, and `passport wait <id>` picks it up again (exit `4`). A decline is said again on every retry for ten minutes, with who and when ("Declined 2 minutes ago by Erin: Not during the freeze."), instead of asking twice. Run the command with `--ask-again` to request again.

`passport scan`, signed in, also tells your workspace which MCP servers your agents use. It is headless and cross-platform, which suits an onboarding script or a scheduled MDM job, and it reports limited configuration metadata only, never paths, commands or arguments, environment values, headers, credentials, endpoint paths or query strings, prompts, files, tool payloads, or traffic. `--check` (CI and pre-commit) never reports. `passport discover`, its old name, still works for one release. See [the scan](/member/scan).

## Diagnose and complete

`doctor` returns every check even when one fails. Human output includes a safe,
actionable fix; `--json` returns a stable report suitable for support automation.
Neither form prints credential values, response bodies, or member identity.

```sh
passport doctor
passport doctor --json
```

`passport version --json` is also offline. It returns `version`, `profileCount`,
`profileSelected`, `selectionSource`, `next`, and optional `endpoint`/`profile`
fields. `passport ready --json` runs the local, authentication, server, and
exact CLI-protocol preflight and returns `ready`, `ok`, auth/profile context,
`server`, and `checks`; gate on its `ready` value and exit code rather than
parsing human output. Not signed in, `doctor` and `ready` exit 2.

Install generated completion in the standard location for your shell:

```sh
# Zsh
mkdir -p ~/.zfunc
passport completion zsh > ~/.zfunc/_passport

# Bash
mkdir -p ~/.local/share/bash-completion/completions
passport completion bash > ~/.local/share/bash-completion/completions/passport

# Fish
mkdir -p ~/.config/fish/completions
passport completion fish > ~/.config/fish/completions/passport.fish
```

## JSON and exit-code contract

With `--json`, stdout contains exactly one JSON value. Hints and warnings go to stderr, so an agent can pipe results without stripping human output. JSON errors have this stable shape:

```json
{
  "error": "A short message",
  "cause": "approval_pending",
  "exitCode": 4,
  "approvalId": "optional",
  "app": "optional",
  "hint": "optional safe remediation",
  "next": [{ "argv": ["passport", "status"], "description": "optional concrete action" }],
  "retry": { "command": "run", "tool": "optional", "waitSeconds": 120, "arguments": "reuse_original" },
  "remediation": { "action": "optional_machine_action", "description": "safe guidance" }
}
```

| Exit | Meaning                                                                                                                                            |
| ---: | -------------------------------------------------------------------------------------------------------------------------------------------------- |
|    0 | Success.                                                                                                                                           |
|    1 | Network, server, or ambiguous execution error. Do not retry automatically.                                                                         |
|    2 | Authentication or profile selection is missing. Run `passport profiles`, `passport use <name>`, or `passport login`.                               |
|    3 | A personal app connection or member action is required. Follow `next` or `remediation`; agent tokens fail fast rather than wait for browser OAuth. |
|    4 | Approval is pending. The result includes the approval id.                                                                                          |
|    5 | Policy, a data check, agent selection, or approval denial blocked the call.                                                                        |
|    6 | Usage error or unknown tool.                                                                                                                       |

`passport run --wait <sec>` retries only a definite `approval_pending` response. It never retries a timeout or network failure because the execution outcome could be ambiguous. When a failure names an approval, human output also prints `Open in Passport: <url>` so a person can decide it.

For `passport describe <tool> --json`, `tool` and `parameters` remain the
Passport-native fields. The response also includes the conventional aliases
`name` (same value as `tool`) and `inputSchema` (same value as `parameters`);
agents can use either vocabulary without translating tool definitions.

## Profiles and attribution

The default profile uses `cli` as its policy agent. Login activates the newly completed profile. When no explicit or environment selector and no valid active profile are present, CLI 0.8.1 detects exactly one CLI-owned profile (`client: "cli"` or the exact legacy `cli@<workspace>` shape) and makes that existing profile active. When several profiles are stored, `passport profiles` lists them and `passport use <name>` changes the local active profile without contacting Passport. If more than one CLI candidate remains, Passport refuses to guess and asks for an explicit selector. Scripts should use an explicit selector so they cannot accidentally run against another workspace.

```sh
passport profiles
passport use cli@work
passport status --profile cli@work
passport search "issues" --profile cli@work
```

To keep app selection and Activity distinct for a specific terminal agent, create a per-agent profile:

```sh
passport login \
  --cloud https://passportmcp.com \
  --workspace <workspace-id> \
  --agent claude-code \
  --profile claude-code@work

PASSPORT_PROFILE=claude-code@work passport search "issues"
passport status --profile claude-code@work
```

Passport can also add cooperative caller detail from known agent environment variables. `--caller <id>` takes precedence. Activity labels it as self-reported, for example **Passport CLI · Codex via CLI**; the authenticated member or agent and the policy agent remain separate identities.

OpenCode is a first-class policy identity too, but it is not listed in the **Add agent** hub, so set it up with the CLI. Use `--agent opencode --profile opencode@work` when its selection and Activity should remain distinct from other terminal agents.

## Headless, CI, and cron

For scripts and CI, create an agent token with **Add agent › A script or job** on [Agents](https://passportmcp.com/#agents?add=token), set `PASSPORT_AGENT_KEY` to it, and inject it and the workspace endpoint through your CI secret store. Environment mode works without `passport login` and writes no local credential file.

```sh
export PASSPORT_AGENT_KEY='<agent-token>'
# Passport's one URL: the agent token names its own workspace.
export PASSPORT_ENDPOINT='https://passportmcp.com/mcp'

passport status --json
passport search "failed builds" --json
passport run sentry_list_issues '{"status":"unresolved"}' --json
passport version --json
passport ready --json
```

Agent tokens can inspect status and call allowed tools, but cannot mint a person's sign-in link. Use `passport connect` from an interactive member profile when an app needs personal OAuth.

Legacy agent tokens are non-interactive: they do not create action-time member
approval prompts. Use a member profile for an operation that must pause for a
human's one-off approval.

<Note>
  The CLI never wraps provider APIs directly and never bypasses the gateway. It calls Passport's governed meta-tools and
  MCP resource/prompt methods, so CLI and MCP usage share one policy and audit pipeline.
</Note>
