title: "Discovered agents"
description: "Find AI connections configured outside Passport and bring them under control."

**Agents → Discovered** shows Enterprise admins the AI connections people configured outside Passport: MCP connections set up directly in supported local agents, found by `passport scan` on members' computers.

Agents connected through Passport are on the **Everyone** tab. See [Manage connected agents](/admin/client-fleet#manage-the-workspace). Your own agents are on **Yours**, the same page every member sees.

## Connections outside Passport

Open **Agents → Discovered**. Each finding becomes a clear decision:

- approve the direct connection;
- ask the owner to move it behind Passport;
- allow it temporarily; or
- ask the owner to remove it.

<Warning>
  Scans report configuration, not usage. A finding means a connection was present during a scan. It does not prove that
  anyone used it.
</Warning>

### Review findings

**Discovered** lists every finding in one list grouped by status: **Needs decision** first, then **In progress** and **Resolved**. Empty groups are hidden. The same MCP found in several agents is one finding.

Each row shows the connection's name, its type (**Local tool**, or the remote server's host), where it was found (for example, `1 agent on 1 computer`), when a scan last saw it, and its status. Statuses use plain words, such as **New**, **Moving to Passport**, **Now goes through Passport**, and **Allowed outside Passport**. Choose **Review** to decide on a finding that needs a decision.

For each item, review:

- who owns it and how they described its purpose;
- which supported agents contain it;
- whether it could be routed through Passport; and
- the current admin decision.

Members can describe a connection as **Work**, **Evaluating**, **Personal**, or **Not needed**. This is context they provide, not a conclusion Passport draws from their activity.

### How scans reach Passport

Every finding comes from the Passport CLI. On a member's computer, run:

```sh
passport scan
```

Signed in, the scan reads supported global configuration for Claude Desktop, Claude Code, Cursor, VS Code, and Codex and submits the limited report described below, using the Passport CLI profile on that computer. Without a sign-in, or with `--check`, it stays on the computer. The command is headless, so it fits an onboarding script, a login hook, or a scheduled MDM job. (`passport discover`, its old name, still works for one release.) Daily is a good cadence, because a source that has not reported for seven days stops counting as current coverage.

Managed policy has three responses:

| Response                                               | `passport scan` behavior                                                             |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Observe only                                           | Report findings and always exit successfully.                                        |
| Require routing through Passport                       | Exit `5` while any active direct connection lacks an explicit approval or exception. |
| Report scans as failed when a connection isn't allowed | Exit `5` when an active direct connection has an admin decision of **Remove**.       |

Your endpoint-management system decides what to do with exit code `5`, such as notify, quarantine, or start its own remediation. Passport does not silently edit a managed device.

### What happens on a member's computer

`passport scan` only reads supported configuration files, and Passport never edits them. A **Route through Passport** or **Remove** decision is a request to the owner, who makes the change in the agent that holds it; the next scan confirms the result.

### Coverage and scan policy

**Discovered** says how many people's computers reported a scan this week. With managed scans, a gap is a warning; in Personal (opt-in) mode it's a quiet note, and it appears only once someone has scanned. Choose **See who's missing** to list the people whose computers haven't sent a scan, whose last scan is over a week old, or whose last scan couldn't read agent settings. Project-level configuration, hosted agents, and computers that never run `passport scan` signed in are outside coverage.

Until the first scan arrives, **Discovered** shows how to set up scans. Afterwards those steps stay under **Set up scans**.

Choose **Scan settings**, the tab's action, to switch between:

- **Personal (opt-in)**: each member decides whether their computer reports scans.
- **Managed work computers**: administrators run `passport scan` through device management (MDM) or an onboarding script. The **Response** setting is available only for managed scans.

Sources older than seven days stop counting as current coverage, but their last findings remain visible.

### What scans do not upload

A scan reports the authenticated member and installation, installation label, agent, safe MCP name, transport type, remote hostname or safe executable class, whether the settings are protected, and scan status and time.

It does **not** upload configuration paths, commands, arguments, environment variables, headers, tokens, endpoint paths, query strings, prompts, files, tool inputs or outputs, or network traffic. A full remote address leaves the computer only after the member reviews and confirms a move.

Failed or permission-denied scans update coverage but do not erase a finding. Passport needs two successful scans without the entry before marking it no longer found.

If a removed entry appears again later, Passport reopens it for review.

## Where this used to be

**Agents → Discovered** was the **Inventory** page, and before that **Discover**. Agents connected through Passport, once Inventory's **Through Passport** tab and before that **Agents → Workspace agents**, are on **Agents → Everyone**. Old links open the matching tab.
