Open in Passport: [Apps › Add app](https://passportmcp.com/#apps?add=1)

An app is the same to people however Passport reaches the provider. It may use an upstream MCP server or a reviewed API driver. Both appear in **Apps**, use the same Connect experience, and are delivered to agents through the same Passport MCP endpoint.

The managed API app is:

- **GitHub API**: repositories, code search, issues, comments, and pull requests

Passport's other apps are GitHub's, Supabase's and Railway's own MCP servers. Every other app was removed on November 17, 2026, to be rebuilt.

## What stays the same

The transport does not change the control plane. Managed API actions use the same:

- catalog request and admin approval flow
- per-person OAuth connection and reconnect flow
- Full, Read-only, and None passes
- person and agent visibility
- per-tool switches, action classes, and drift alerts
- members' rules
- argument and result data checks
- the record, admin changes, metrics, and health views
- workspace, single-app, CLI, and hosted-agent surfaces

If an API driver exposes resources or prompts, Passport namespaces and governs those with the same read pipeline used for MCP resources and prompts.

## OAuth setup

GitHub needs an OAuth client whose callback is:

```text
https://<your-passport-host>/auth/connect-app/callback
```

The hosted service can configure a managed OAuth client with:

```text
PASSPORT_OAUTH_GITHUB_API_CLIENT_ID
PASSPORT_OAUTH_GITHUB_API_CLIENT_SECRET
```

When a managed client is absent, an admin can add the provider-issued client ID and secret in the app setup. Members then connect their own accounts through the same consent screen. Provider access and refresh tokens are encrypted at rest and are never returned to the agent.

<Note>
  Choose the provider scopes required by the actions you enable. Passport's passes and approvals narrow what an agent
  can invoke, but they do not replace least-privilege OAuth scopes at the provider.
</Note>

## Compatibility

Existing app records and URLs are unchanged. The stored `apps` aggregate remains stable; older records infer their protocol from their existing kind. Managed API apps are additive, so agents and passes keep working without migration.
