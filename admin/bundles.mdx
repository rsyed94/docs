A **bundle** is an Enterprise feature: a named set of tools from several connected apps, with its own connection URL. Use it when an AI assistant should see a tight tool list instead of everything a person can reach.

## Create a bundle

On Enterprise, open **Team setups → Bundles → New bundle**, then:

1. Name the bundle (and optionally describe it).
2. Under **Apps**, pick the apps the bundle draws from. Each chip shows how many tools that app serves.
3. For each app, choose what the bundle includes:
   - **Read-only** (the default): every tool Passport classes as a read, including read tools the app adds later.
   - **Everything**: every tool the app serves, including tools it adds later.
   - **Custom**: only the tools you check. Search across every Custom list, filter by **Read**, **Write**, or **Destructive**, use **Select all**, or Shift-click to select a range. Tools the app adds later stay out.
4. Set who can use it (workspace, teams, or selected people) and the default access. New bundles start **read-only** unless you widen them, so people with read-only access get only the read tools, whatever each app's choice.
5. Check the summary at the bottom (for example `14 tools · 3 apps · 12 read, 2 write`), then select **Create bundle**. Passport creates a stable key and a target like `bundle:<key>`.

A bundle never serves a tool its app withholds. Tools that are switched off on the app, held for review after they appear or change upstream, or held because their definition looked unsafe stay out of every bundle, in every mode. Once you approve a held tool on the app, it joins Read-only and Everything bundles on its own (a Custom list adds it only if you check it).

Bundles created before these modes existed open as **Custom** with their original tools and keep working exactly as before. Switch an app to Read-only or Everything to include tools it adds later.

Bundles expose tools only, not upstream resources or prompts.

## Connect an AI assistant

Point the assistant at the bundle connection URL:

```
https://<your-passport-host>/b/<bundle-key>/mcp
```

Sign-in works the same way as the workspace connection. People with no access to the bundle do not see it. Bundle connections always list tools flat (they ignore the workspace flat/apps/compact setting). See [Tool discovery modes](/concepts/discovery).

## Include a bundle in a team setup

In the [team setup](/admin/team-setups) editor, choose the bundles the setup includes, then save and publish. Members of that setup who can already use a bundle see it under **Setup** with its connection URL and a copy button.

Including a bundle does not grant access. If someone cannot use the bundle, it does not appear for them. Deleting a bundle removes it from every setup.

## Access and rollout

Bundle access uses the same full / read-only / none model as apps, with workspace, team, and per-person layers. Disabling or deleting a bundle removes its tools right away. Removing an app from the workspace also drops that app's tools from every bundle.

Free and Pro cannot create or serve bundles.
