Open in Passport: [Rules › Everyone](https://passportmcp.com/#rules?scope=everyone)

Data checks inspect calls that pass through Passport. They check arguments before an app receives them and the complete result before an agent sees it, including structured data and resource metadata. Images, audio, and binary content are size-limited but aren't read as text.

Built-in secret detection protects every plan. On Enterprise, owners also get **Data checks** at the foot of [Rules](https://passportmcp.com/#rules?scope=everyone), switched to **Everyone**, where they add their own.

## The list

Each check is one row: its name, what it does (**Blocks**, **Redacts**, or **Alerts only**), what it scans (**Inputs and results**, **Inputs**, or **Results**), and which apps (**All apps**, or the ones you picked). Built-in checks read **Always on**. A custom check has a switch, and opening it lets you edit it. **Needs review** marks an older check whose pattern you should look at again; **Retired** marks one Passport can no longer run.

## Add a data check

**Add a data check** opens a library of ready-made checks, grouped by kind. Each is one **Add** away and starts working as soon as you add it. **Write your own** opens a blank check.

A custom check takes a regular expression or a plain phrase, and inspects arguments, results, or both, everywhere or only in selected apps. Regex runs in a bounded, linear-time engine; lookarounds and backreferences aren't supported. A phrase that isn't valid regex is matched literally, ignoring case.

Patterns are limited to 200 characters, and at most 32 enabled checks can apply to one call. A custom check inspects up to 100,000 characters. If a blocking or redacting check receives more, Passport withholds the payload rather than passing an uninspected tail; an alert-only check records that it hit the limit and lets the call through.

Checks also inspect sensitive text split across fields or content blocks. If redaction can't keep a valid response (for example, because it would change a resource address or object key), Passport withholds the response.

A blocked action shows **Blocked** on its task with the check's name. Passport runs blocking checks against the original content before applying redactions, so one check can't hide a match from another.

## Built-in secret detection

Every workspace has a check that catches common credentials before they cross the wire in either direction, including:

- AWS access keys
- GitHub tokens
- Slack tokens
- OpenAI keys
- Stripe keys
- PEM private keys
- Passport's own session, access, refresh, and agent tokens
- password assignments

It scans the full text payload up to 5 MB, including secrets deep inside a file read or database result. With a larger payload, it withholds the payload instead of passing an uninspected tail.

## Runtime security

On Enterprise, runtime security also looks for categories such as instruction override, hidden instruction characters, secret-exfiltration instructions, access-control bypass, destructive commands, and resource abuse, in tool descriptions, arguments, and results.

Findings store only bounded metadata: app, tool, phase, category, severity, action, reason, and a one-way fingerprint. Passport never stores the matching request or result in a finding. Findings can be streamed as metadata-only security events. See [SIEM and OTLP export](/enterprise/siem-export).

<Warning>
  Runtime security is explainable and deliberately conservative. It doesn't claim to catch every malicious
  instruction.
</Warning>

## The record stays clean

Content a check flags is scrubbed before the action is recorded, so a blocked credential can't reappear in Work or an export. The exception is a custom alert-only check, which is meant to surface the matched content for review.
