Everyone can manage their own connections from **Agents**. Enterprise admins can also see and manage connections across the workspace.

## Manage your own agents

Open **Agents → My agents** to:

- add an agent;
- see whether Passport has observed it;
- choose which available apps it can see;
- troubleshoot or reconnect it;
- remove a duplicate Desktop compatibility connection; or
- disconnect it immediately.

Free and Pro use the same personal page without the two tabs.

## Manage the workspace

On Enterprise, open **Agents → Workspace agents**. You can search by person or agent, inspect agents that are unused or out of date, and revoke a connection so it must sign in again.

The workspace list shows real observed connections. Opening setup instructions alone does not create a connected-agent record.

## Understand agent names

For a dynamic agent, Passport uses the name or title reported by the MCP agent,
falling back to its registered connection label. A reported version is retained
when available. Recognized agents keep Passport's standard name.

These names help identify connections in Agents, Activity, approvals, and
exports. They are self-reported context: claiming the name of a recognized agent
does not satisfy registered-agent policy or grant access.

If a connection still appears as **agent**, keep it open and ask it to list
Passport tools, then refresh Agents. An agent that supplies no identity and has
no specific connection label keeps the generic name.

## Set agent policy

Open **Settings → Agent access**:

- **Allow dynamic agents** — whether unrecognized agents may connect
- **Require registered agents** — only agents Passport recognizes (or you have registered) may connect

These controls require Enterprise. If the workspace downgrades, the saved policy is not enforced until Enterprise is active again.

## Team defaults

[Agent defaults](/admin/client-defaults) choose which already-allowed apps appear by default in an agent for a team. They never grant access.
