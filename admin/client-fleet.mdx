Open in Passport: [Agents › Everyone](https://passportmcp.com/#agents?scope=everyone)

This page covers **Agents** in both views. Everyone, admins included, manages their own agents on [Agents](https://passportmcp.com/#agents). On Pro and Enterprise, admins switch it to **Agents › Everyone** to see every agent in the workspace. To put Passport in every agent at once, see [Roll out to your company](/admin/rollout).

## Manage your own agents

Open **Agents** to see **Your agents**: one list of every agent you own, whatever kind it is. Members and admins see the same page.

- **On a computer**: Claude Code, Claude Desktop, Cursor, and the rest. There is one row for each agent on each computer: Claude Code, Claude Desktop, and Claude.ai are separate agents, and Claude Code on two laptops is two rows. Interactive Passport CLI profiles on one computer share one **Passport CLI** row.
- **Cloud**: Codex cloud, Claude Code on the web, and GitHub Actions, running as an agent you own.
- **Tokens**: an agent token a script, CI job, or hosted workflow uses instead of signing in.

Each row says what kind of agent it is and where (for example **On Maya's MacBook Pro**, **Cloud · GitHub Actions**, **Token · runs as itself**, or **Token · acts for Priya**) and when it was last used. One chip says its state: **Active**, **Stopped**, **Needs sign-in**, or **Not used yet**. A row has a button only when something needs doing: **Reconnect** when its sign-in expired, **Update** when a Passport CLI or local setup is behind the newest version (see [Keep agents up to date](/member/updates)), or **Remove duplicate** when a local setup shows the same tools twice next to a working account connection. When agents need you to sign in again, a row at the top says how many, and **Show** narrows the list to them.

Filter the list with **All**, **On a computer**, **Cloud**, or **Tokens**; each shows its count. `#agents?kind=token` opens the Tokens filter. A token whose agent has no live token left leaves the list; **Revoked and expired** at the foot of the Tokens filter shows them.

### An agent's page

Every row opens its agent's page (`#agents/mine/<agent>`, `#agents/cloud/<id>`, or `#agents/token/<id>`). It shows only what applies:

- **Stop**, the page's one action, for the agent's owner and admins. It asks first. For a cloud agent or a token, every call the agent makes is refused until someone resumes it; its tokens and rules stay as they are, and a banner says who stopped it and when, with **Resume**. For an agent on a computer, Stop ends its current work and refuses its next request; its next session starts fresh. Everyone else sees the page read-only.
- **Recent work**: its last five sessions, and **See all**, which opens Sessions filtered to that agent.
- **Connection** (agents on a computer): **Test connection**, the fix for anything broken, its guard on each computer, each sign-in it uses (with **Rename** for that computer and **Disconnect** for one sign-in), and **Limit apps for this agent**.
- **Tokens** (cloud agents and tokens): one row per live token with its last four characters, when it was created and last used, and when it expires. **Rotate** and **Revoke** are in the row's menu, and **Create token** adds another; a new token is shown once. Revoked and expired tokens fold into a disclosure. See [Agent tokens, their owners, and rotation](/admin/agents-and-access#agent-tokens-their-owners-and-rotation).
- **Runs as**: whether it runs as itself or acts for a person, and who its approvals go to.
- **Remove agent**, at the foot, after a confirm that says what stops.

### Add an agent

**Add agent** opens one dialog with three choices: **An agent you use** (it opens on the agent your team setup recommends, or one a Discover scan found, and otherwise on Claude; guided setups end with **Test connection**), **A cloud agent**, and **A script or job**, which creates an agent token. Owners and admins create tokens; anyone else is asked to ask an admin. A new cloud agent or token opens on its own page, which shows its token once.

## Manage the workspace

On Pro and Enterprise, admins switch **Agents** from **Mine** to **Everyone**, the same selector Sessions uses. Everyone has one row per agent connected through Passport, such as Claude Code or Cursor, with who uses it (for example, `1 person · 2 connections`), the newest Passport version it runs and how many connections are out of date, and when it was last active. When connections are out of date, **Update all N** asks every computer that can update itself to install the new version on its next run. Once the list has 10 or more rows, search finds a person, agent, or computer.

Open an agent to see its **connections**, one per person per computer. Each shows its owner (linked to their person page), the computer, the guard state, Passport's version, when it was last active, and **Disconnect**.

- **Idle connections** haven't been used in 30+ days. Disconnect the ones you don't recognize, one at a time or with **Disconnect N idle**.
- **Version** shows only for software Passport ships: Passport CLI and the local bridge, shown as, for example, `Passport 0.11.3`. Agents that sign in with a browser update from their own vendor, so their version shows as `—`.
- **Out of date** marks connections running a Passport older than the newest published version. Once asked for, the cell says **Updates on next run**, then **Restart to finish** for a local bridge whose agent still runs the old version, or **Update didn't finish** with the reason.

Disconnecting cuts access right away, after a confirm that names the agent, person, and computer. Its owner must sign in again. The list shows real observed connections; opening setup instructions alone does not add a row.

A person's page shows their agents on computers under **Agents**, with each guard state and fix. MCP servers people set up outside Passport are on [Agents › Discovered](/admin/discovered-agents).

## Understand agent names

For a dynamic agent, Passport uses the name or title reported by the agent,
falling back to its registered connection label. A reported version is retained
when available. Recognized agents keep Passport's standard name.

These names help identify connections in Agents, Sessions, activity, approvals, and
exports. They are self-reported context: claiming the name of a recognized agent
does not satisfy registered-agent policy or grant access.

If a connection still appears as **agent**, keep it open and ask it to list
Passport tools, then refresh Agents. An agent that supplies no identity and has
no specific connection label keeps the generic name.

## Set agent policy

Open [Rules › Team › Which agents can connect](https://passportmcp.com/#rules/team?section=agents) and choose which agents can connect:

- **Any agent**: people can connect any agent, including ones Passport doesn't recognize.
- **Known agents for new connections**: new connections must use an agent Passport recognizes. Other agents already connected keep working.
- **Known agents only**: only recognized agents can connect, and other agents are blocked even if already connected. Agent tokens still work.

These controls require Enterprise. If the workspace downgrades, the saved policy is not enforced until Enterprise is active again.

## Team defaults

[Team setups](/admin/team-setups#what-agents-start-with) choose which already-allowed apps each agent starts with for a team. They never grant access.

## Lock the guard on

By default the guard lives in each person's own agent settings, so they can turn it off. **Lock it** on [Agents › Rollout](/admin/rollout#lock-the-guard-on) puts Passport's guard and audit hooks in each agent's managed (system) settings instead, where people can't remove them. Managed settings run a small launcher owned by root at `/Library/Application Support/Passport/bin/passport` (macOS), `/opt/passport/bin/passport` (Linux), or `C:\ProgramData\Passport\bin\passport.cmd` (Windows). It hands off to each person's own Passport CLI; until that's set up, commands run as usual.

| Agent       | Lock it                                                                                                                                                                                  | Strict adds                                                    |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Claude Code | `hooks` in managed settings, or the drop-in `managed-settings.d/50-passport.json` ([settings](https://code.claude.com/docs/en/settings), [hooks](https://code.claude.com/docs/en/hooks)) | `allowManagedHooksOnly`, and `onFailure: "block"` on the guard |
| Codex       | Hooks in `requirements.toml` run from `managed_dir`, trusted by policy ([managed configuration](https://learn.chatgpt.com/docs/enterprise/managed-configuration))                        | `allow_managed_hooks_only = true`                              |
| Cursor      | The system `hooks.json` ([hooks](https://cursor.com/docs/agent/hooks))                                                                                                                   | `failClosed` on the guard                                      |

**Strict** runs only managed hooks, and blocks a command when the guard can't run (for example, before that person has set Passport up).

Deploy the files from **Agents › Rollout** through MDM, or run this as root on each computer:

```sh
sudo npx passport-bridge@latest init --org <key> --yes --lock [--strict]
```

It writes the launcher and each agent's file, merging with what's there: it replaces only Passport's own entries, and leaves a file it can't merge safely untouched with the fix (for example, managed settings that set `disableAllHooks`, or another `[hooks]` table in `requirements.toml`). Without administrator rights it writes nothing and lists the files to deploy. If you also use claude.ai server-managed settings, add `"managedSourcesBehavior": "merge"` so both apply. The guard shows **Locked** on **Agents** for computers where it's locked.
