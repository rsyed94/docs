Everyone, admins included, manages their own connections from **Agents**. Enterprise admins see every agent in the workspace under [Inventory](/admin/inventory).

## Manage your own agents

Open **Agents** to see **Your agents**. Members and admins see the same page. There is one row for each agent you signed in to, not one per product: a Claude account connection, Claude Desktop, and Claude Code share one **Claude** row, and interactive Passport CLI profiles share one **Passport CLI** row. ChatGPT and Codex are separate setups, so they stay separate rows.

A working agent stays quiet: its row shows where it is used (for example **Used in Claude.ai · Desktop · Code**) and **Last used**, which opens Activity filtered to that agent. A row only asks for something when there is one thing to fix:

- **Reconnect** when an agent's Passport sign-in expired;
- **Update** when a Passport CLI or local setup is behind the newest version in your workspace;
- **Remove duplicate** when a local setup shows the same tools twice next to a working account connection; or
- **Remove** when an agent has not been used in 30 days.

Open an agent to:

- **Test connection**: Passport checks that the agent's sign-in is valid and has been used (or waits for its first request), then says what it can reach, such as "Claude Code can see 13 apps and 172 tools";
- see each sign-in it uses, with a detail line such as "via Passport Desktop on Sam's MacBook", and **Rename** that computer (only you see the name);
- **Add a connection** on another computer; or **Disconnect** one sign-in immediately; and
- **Limit apps for this agent** to hide some of your apps from it. The disclosure shows a line such as "Sees 3 of 13 apps" only when the agent is limited.

**Add agent** opens on the agent your team setup recommends, or one a Discover scan found on your computer, and otherwise on Claude. Guided setups end with **Test connection**.

## Automations

Owners and admins manage automation keys for scripts, CI, and hosted workflows in **Agents → Automations**. See [Automation credentials](/admin/people-and-teams#automation-credentials). People who own a key but are not admins see only their own keys there and can revoke them.

## Manage the workspace

On Enterprise, open **Inventory**. Its **Through Passport** tab lists every connected agent and its connections (one per person per computer): review connections that are idle or out of date, and revoke a connection so it must sign in again. See [Inventory](/admin/inventory#agents-through-passport).

## Understand agent names

For a dynamic agent, Passport uses the name or title reported by the MCP agent,
falling back to its registered connection label. A reported version is retained
when available. Recognized agents keep Passport's standard name.

These names help identify connections in Agents, Inventory, Activity, approvals, and
exports. They are self-reported context: claiming the name of a recognized agent
does not satisfy registered-agent policy or grant access.

If a connection still appears as **agent**, keep it open and ask it to list
Passport tools, then refresh Agents. An agent that supplies no identity and has
no specific connection label keeps the generic name.

## Set agent policy

Open **Settings → Access → Agents** and choose which agents can connect:

- **Any agent**: people can connect any agent, including ones Passport doesn't recognize.
- **Known agents for new connections**: new connections must use an agent Passport recognizes. Other agents already connected keep working.
- **Known agents only**: only recognized agents can connect, and other agents are blocked even if already connected. Automation keys still work.

These controls require Enterprise. If the workspace downgrades, the saved policy is not enforced until Enterprise is active again.

## Team defaults

[Team setups](/admin/team-setups#what-agents-start-with) choose which already-allowed apps each agent starts with for a team. They never grant access.
