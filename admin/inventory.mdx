title: "Inventory"
description: "See the AI in use across your workspace, whether it goes through Passport, and bring direct connections under control."
---

**Inventory** answers one question for Enterprise admins: what AI is in use in this workspace, and is it going through Passport? It has two tabs:

- **Through Passport**: every agent connected to Passport, its connections, and whether any are idle or out of date.
- **Outside Passport**: MCP connections people configured directly in supported local agents, found by `passport discover` scans.

Your own agents stay on **Agents**, the same page every member sees.

## Agents through Passport

Open **Inventory**. The table has one row per agent, such as Claude Code or Cursor. Each agent has **connections**: one per person per computer. A row shows who uses the agent (for example, `1 person · 2 connections`), the newest Passport version it runs, and when it was last active.

Choose a row to see each connection: its owner (linked to their person page), the computer it runs on, how it connects (**Signs in with browser**, **Through Passport Desktop**, or **Passport CLI**), Passport's version, and when it was last active.

- **Idle connections** haven't been used in 30+ days. Revoke the ones you don't recognize. On an agent's page, **Revoke N idle** revokes all of that agent's idle connections at once.
- **Version** shows only for software Passport ships: Passport CLI and the local Passport bridge (set up by Passport Desktop or by hand), shown as, for example, `Passport 0.11.3`. Agents that sign in with a browser update from their own vendor, so their version shows as `—`.
- **Out of date** marks connections running Passport two or more versions behind the newest Passport version in use. Its owner should update.
- Once an agent list or an agent's page has 10 or more rows, search finds a person, agent, or computer.

Revoking a connection cuts its access right away. Passport asks you to confirm first and names the agent, person, and computer. Its owner must reconnect it. The list shows real observed connections; opening setup instructions alone does not add a row. When people in the workspace run Passport Desktop, its rollout summary appears above the table.

## Connections outside Passport

Open **Inventory → Outside Passport**. Each finding becomes a clear decision:

- approve the direct connection;
- ask the owner to move it behind Passport;
- allow it temporarily; or
- ask the owner to remove it.

<Warning>
  Scans report configuration, not usage. A finding means a connection was present during a scan. It does not prove
  that anyone used it.
</Warning>

### Review findings

**Outside Passport** lists every finding in one list grouped by status: **Needs decision** first, then **In progress** and **Resolved**. Empty groups are hidden. The same MCP found in several agents is one finding.

Each row shows the connection's name, its type (**Local tool**, or the remote server's host), where it was found (for example, `1 agent on 1 computer`), when a scan last saw it, and its status. Statuses use plain words, such as **New**, **Moving to Passport**, **Now goes through Passport**, and **Allowed outside Passport**. Choose **Review** to decide on a finding that needs a decision.

For each item, review:

- who owns it and how they described its purpose;
- which supported agents contain it;
- whether it could be routed through Passport; and
- the current admin decision.

Members can describe a connection as **Work**, **Evaluating**, **Personal**, or **Not needed**. This is context they provide, not a conclusion Passport draws from their activity.

### How scans reach Passport

Every finding comes from the Passport CLI. On a member's computer, run:

```sh
passport discover
```

The command is headless and needs no desktop app, so it fits an onboarding script, a login hook, or a scheduled MDM job. It scans supported global configuration for Claude Desktop, Claude Code, Cursor, VS Code, and Codex, submits the limited report described below, and uses the signed-in Passport CLI profile on that computer. Daily is a good cadence, because a source that has not reported for seven days stops counting as current coverage.

Managed policy has three responses:

| Response                                               | `passport discover` behavior                                                         |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Observe only                                           | Report findings and always exit successfully.                                        |
| Require routing through Passport                       | Exit `5` while any active direct connection lacks an explicit approval or exception. |
| Report scans as failed when a connection isn't allowed | Exit `5` when an active direct connection has an admin decision of **Remove**.       |

Your endpoint-management system decides what to do with exit code `5`, such as notify, quarantine, or start its own remediation. Passport does not silently edit a managed device.

<Note>
  Passport Desktop no longer scans local agent configuration. Desktop is sign-in, connection repair, apps, activity,
  and approvals; `passport discover` is the only source of outside-Passport findings.
</Note>

### What happens on a member's computer

`passport discover` only reads supported configuration files, and Passport never edits them. A **Route through Passport** or **Remove** decision is a request to the owner, who makes the change in the agent that holds it; the next scan confirms the result.

### Coverage and scan policy

**Outside Passport** says how many people's computers reported a scan this week. With managed scans, a gap is a warning; in Personal (opt-in) mode it's a quiet note, and it appears only once someone has scanned. Choose **See who's missing** to list the people whose computers haven't sent a scan, whose last scan is over a week old, or whose last scan couldn't read agent settings. Project-level configuration, hosted agents, and computers that never run `passport discover` are outside coverage.

Until the first scan arrives, **Outside Passport** shows how to set up scans. Afterwards those steps stay under **Set up scans**.

Choose **Scan settings** on **Outside Passport** to switch between:

- **Personal (opt-in)**: each member decides whether their computer reports scans.
- **Managed work computers**: administrators run `passport discover` through device management (MDM) or an onboarding script. The **Response** setting is available only for managed scans.

Sources older than seven days stop counting as current coverage, but their last findings remain visible.

### What scans do not upload

A scan reports the authenticated member and installation, installation label, agent, safe MCP name, transport type, remote hostname or safe executable class, whether the settings are protected, and scan status and time.

It does **not** upload configuration paths, commands, arguments, environment variables, headers, tokens, endpoint paths, query strings, prompts, files, tool inputs or outputs, or network traffic. A full remote address leaves the computer only after the member reviews and confirms a move.

Failed or permission-denied scans update coverage but do not erase a finding. Passport needs two successful scans without the entry before marking it no longer found.

If a removed entry appears again later, Inventory reopens it for review.
