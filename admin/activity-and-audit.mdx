title: "Activity and audit records"
description: "Review tool calls and admin changes, export them on Pro, and stream them on Enterprise."
---

Passport keeps two separate records:

- **Activity** records calls made through Passport.
- **Admin activity** records privileged workspace changes.

Keeping them separate makes it clear whether an event came from an agent or from an administrator changing the workspace.

## Your activity

Everyone can open **Sessions → All activity** to see their own calls. A row shows the app, action, agent, outcome, and timing.

- **Allowed** means the call completed.
- **Blocked** means access, Autopilot rules, an approval, or a data check stopped it. The row says which in one line, such as "No access to GitHub in Passport", "This tool is switched off for GitHub", or the data check's name, and links to where that's set: the app's **Access** or **Tools** tab, **Apps → Setups**, **Rules → Data checks**, or the rule. Session rows say the same.
- **Error** means the call was allowed but did not complete successfully.

Actions read the same everywhere. A CLI command reads like "railway redeploy" under the app **Railway CLI**, everyday commands appear under **Shell**, and tools read like "delete branch". A command Passport couldn't read says **Not checked**.

## What agents say they're doing

Claude Code writes a one-line description of each command it runs, such as "Run the bridge tests". Admins can turn on **Settings → Workspace → Show what agents say they're doing** so that line becomes the action's label in Sessions, with the command's name and target still beside it, and the session's first described change shows under its title as its goal. It's off by default.

The description is redacted on the member's computer before it's sent: paths are cut to their last name, and one containing anything that looks like a key, token, or email address isn't sent at all. Passport keeps it with the activity for 90 days. Admins on Pro and Enterprise see other members' descriptions where they already see their sessions. Turning it off stops Passport keeping new ones and hides the ones it kept. See [what the hook records](/member/cli-hook#what-it-records).

## Find work

**All activity** shares the search box and filters of [Sessions](/member/sessions#search), such as `project:acme-api`, `cmd:"gh pr merge"`, `env:unplaced`, or `outcome:failed`. Its quick filters are **Notable**, **Production changes**, **Failed**, and **Asked**. Search covers your whole history, and the address keeps it, so a filtered view is a link you can share. **Open in All activity** on a session shows that session's actions however old it is.

## Workspace activity

On Pro and Enterprise, admins switch **All activity** from **Mine** to **Everyone**, the same selector Sessions uses, to see calls across the workspace. Filters cover person, apps, agent, team, result, time, and search text. You can select several apps at once. Filtered views have shareable URLs, and links elsewhere in Passport, such as data check findings and alerts, say **Open in All activity** and open the matching view. Older Activity links open the same view with their filters kept. Export the filtered view as CSV or JSONL.

On Enterprise, once managed runs exist, a **Runs** tab sits beside the log with durable action receipts and their approval history.

A person's own timeline is the **Activity** tab on their person page, with its own CSV export.

Passport CLI may add an optional **via CLI** label so the record can distinguish tools such as Codex and Claude Code. That label is self-reported; the signed-in person or agent and the agent policy remain authoritative.

Dynamic agents can appear by their reported name or title, with their
reported version retained when available. Like the CLI caller label, this is
self-reported context; it does not change the authenticated identity or grant
access. See [agent names](/admin/client-fleet#understand-agent-names).

## Admin activity

Open **Settings → Admin activity** on Pro or Enterprise to review changes such as:

- approving or removing an app;
- changing a role or team;
- creating or editing a data check;
- changing agent policy; or
- generating or revoking a SCIM token.

Each entry records the actor, action, target, time, and a concise description of the change.

## Export

<CardGroup cols={2}>
  <Card title="Activity export" icon="table">
    `GET /export/activity.csv` and `GET /export/activity.jsonl` require Pro or Enterprise. They accept the same
    `member`, `app`, `outcome`, `department`, `via`, `since`, and `q` filters as the Everyone view of All activity.
    Repeat `app` to include several apps. In this API, `department` means team, `via` means agent, and `q` is search
    text.
  </Card>
  <Card title="Audit export" icon="file-lines">
    `GET /export/audit.csv` exports the privileged-action trail and also requires Pro or Enterprise.
  </Card>
</CardGroup>

Every plan lets an admin download a full workspace backup. On Free, use **Settings → Workspace essentials → Manage workspace → Advanced**. On Pro and Enterprise, use **Settings → Workspace → Workspace backup**. A backup is for recovery and support, not for security monitoring.

<Note>
  Passport scrubs sensitive content before Activity is stored. A blocked credential cannot reappear through an export.
  See [Data checks](/admin/data-checks).
</Note>

## Stream to your SIEM

Enterprise can stream both record types to a SIEM over HTTP or to an OpenTelemetry collector. See [SIEM and OTLP export](/enterprise/siem-export).
