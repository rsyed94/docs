Open in Passport: [Sessions › All activity](https://passportmcp.com/#sessions/activity)

Passport keeps two separate records:

- **Activity** records every action made through Passport.
- **Admin activity** records privileged workspace changes.

Keeping them separate makes it clear whether an event came from an agent or from an administrator changing the workspace.

## Your activity

Everyone can open **Sessions › All activity** to see their own actions. A row shows the app, action, agent, result, and time, such as "Today 3:40 PM".

- **Ran** means the action completed.
- **Blocked** means access, Autopilot rules, an approval, or a data check stopped it. The row says which in one line, such as "No access to GitHub in Passport", "This tool is switched off for GitHub", or the data check's name, and links to where that's set: the app's **Access** or **Tools** tab, **Apps › Setups**, **Rules › Data checks**, or the rule. Session rows say the same.
- **Failed** means the action ran and returned an error.
- **Flagged** means a data check matched it and recorded it without blocking it.
- **Asked** means Passport asked a person first.

Each fact on a row links once: the app to its page, the person to their person page, the agent to its page, the session to its timeline, and the deciding rule to **Rules**. See [Status words](/concepts/status-words) for every result word.

Actions read the same everywhere. A CLI command reads like "railway redeploy" under the app **Railway CLI**, everyday commands appear under **Shell**, and tools read like "delete branch". A command Passport couldn't read says **Not checked**.

## What agents say they're doing

Claude Code writes a one-line description of each command it runs, such as "Run the bridge tests". Admins can turn on **Show what agents say they're doing** in [Settings › Workspace](https://passportmcp.com/#settings/workspace) so that line becomes the action's label in Sessions, with the command's name and target still beside it, and the session's first described change shows under its title as its goal. It's off by default.

The description is redacted on the member's computer before it's sent: paths are cut to their last name, and one containing anything that looks like a key, token, or email address isn't sent at all. Passport keeps it with the activity for 90 days. Admins on Pro and Enterprise see other members' descriptions where they already see their sessions. Turning it off stops Passport keeping new ones and hides the ones it kept. See [what the hook records](/member/cli-hook#what-it-records).

## Find work

**All activity** has one filter bar, the same for **Mine** and **Everyone**: a search box, **App**, **Agent**, **Result** (**Ran**, **Blocked**, **Failed**, **Flagged**, or **Asked**), a time window (any time unless you pick one), **Refresh**, and **Export**. Admins viewing **Everyone** also get **Person** and **Team**. On a phone the selects fold behind **Filters**.

The search box takes the same words and filters as [Sessions](/member/sessions#search), such as `project:acme-api`, `cmd:"gh pr merge"`, `env:unplaced`, or `outcome:failed`. Every filter lives in the address, such as `#sessions/activity?app=github&outcome=failed&since=7d`, so reload, Back, and a shared link keep it, and switching between **Mine** and **Everyone** keeps every filter except person and team. **Open in All activity** on a session shows that session's actions however old it is.

When nothing matches, the empty state offers one way out: **Clear filters**, **Show any time** when only the window narrows it, or **Show routine tool lookups** when only those match.

## Workspace activity

On Pro and Enterprise, admins switch **All activity** from **Mine** to **Everyone**, the same selector Sessions uses, to see actions across the workspace (`#sessions/activity?scope=everyone`). Links elsewhere in Passport, such as data check findings and alerts, say **Open in All activity** and open the matching view. Older Activity links open the same view with their filters kept.

**Export** downloads the filtered view as CSV in both scopes: **Mine** exports only your own actions, and **Everyone** the workspace's. Each export is recorded in admin activity.

On Enterprise, once managed runs exist, a **Runs** tab sits beside the log with durable action receipts and their approval history.

A person's own timeline is the **Activity** tab on their person page.

Passport CLI may add an optional **via CLI** label so the record can distinguish tools such as Codex and Claude Code. That label is self-reported; the signed-in person or agent and the agent policy remain authoritative.

Dynamic agents can appear by their reported name or title, with their
reported version retained when available. Like the CLI caller label, this is
self-reported context; it does not change the authenticated identity or grant
access. See [agent names](/admin/client-fleet#understand-agent-names).

## Admin activity

Open [Settings › Workspace](https://passportmcp.com/#settings/workspace) on Pro or Enterprise and choose **View activity** under **Admin activity** to review changes such as:

- approving or removing an app;
- changing a role or team;
- creating or editing a data check;
- changing agent policy;
- generating or revoking a SCIM token;
- marking a data check finding reviewed; or
- resending or revoking an invite, and exporting Activity.

Each entry records the actor, action, target, time, and a concise description of the change.

## Export

<CardGroup cols={2}>
  <Card title="Activity export" icon="table">
    `GET /export/activity.csv` and `GET /export/activity.jsonl` export the workspace and require Pro or Enterprise.
    They accept the same `member`, `app`, `outcome`, `department`, `via`, `since`, and `q` filters as the Everyone view
    of All activity. Repeat `app` to include several apps. In this API, `department` means team, `via` means agent, and
    `q` is search text. `GET /api/my/activity.csv` exports only your own actions.
  </Card>
  <Card title="Audit export" icon="file-lines">
    `GET /export/audit.csv` exports admin activity and also requires Pro or Enterprise.
  </Card>
</CardGroup>

Every plan lets an admin download a full workspace backup. On Free, choose **Manage workspace** on **Settings › Account**, then **Workspace backup** under **Advanced**. On Pro and Enterprise, use **Workspace backup** on **Settings › Workspace**. A backup is for recovery and support, not for security monitoring.

<Note>
  Passport scrubs sensitive content before Activity is stored. A blocked credential cannot reappear through an export.
  See [Data checks](/admin/data-checks).
</Note>

## Stream to your SIEM

Enterprise can stream both record types to a SIEM over HTTP or to an OpenTelemetry collector. See [SIEM and OTLP export](/enterprise/siem-export).
